# 企業年會與尾牙抽獎系統：現行抽獎演算法技術說明書

本文件旨在向活動主辦單位、技術人員及公司同仁完整說明本系統現行的抽獎演算法設計原理、數學證明及公平性保障機制。

## 1. 執行摘要 (Executive Summary)

本系統的抽獎機制採用**「現代 Fisher-Yates (Knuth-Durstenfeld) 洗牌演算法」**，並整合瀏覽器底層的**「Web Crypto API 密碼學安全亂數產生器（CSPRNG）」**與**「無模數偏差（No Modulo Bias）拒絕取樣」**技術。

本系統確保：
1. **嚴格均勻分佈（Uniform Distribution）**：候選池中 $N$ 位同仁，每位同仁在任何一次抽獎中被抽中的機率**精確相等**，皆為 $\frac{1}{N}$。
2. **無偏差（Unbiased）**：完全捨棄 JavaScript 常見的 `sort()` 排序洗牌缺陷，排除同仁排列位置、部門排序或名單匯入先後所導致的機率傾斜。
3. **防預測與防重現（Cryptographic Entropy）**：使用作業系統級熵源（Entropy Source），而非一般的偽隨機數產生器（PRNG），無法透過時間戳或演算法規律進行人為預測或破解。

## 2. 為什麼捨棄傳統 JavaScript 抽獎寫法？

在許多常見的網頁抽獎系統中，常會看到以下這行簡短的程式碼：

```javascript
// ❌ 錯誤且有重大偏差的寫法（本系統已徹底廢除）：
const winners = candidates.sort(() => 0.5 - Math.random());
```

這行程式碼表面上看似能打亂名單，但在電腦科學與統計學上存在兩大致命缺陷：

| 缺陷項目 | 傳統寫法 `sort(() => 0.5 - Math.random())` | 本系統採用的 `Fisher-Yates + Web Crypto` |
| :--- | :--- | :--- |
| **數學均勻性** | **不均勻（有偏差）**。瀏覽器引擎（如 Chrome V8 的 TimSort）要求比較函式必須符合數學傳遞律（若 $A > B$ 且 $B > C$ 則 $A > C$）。隨機比較會破壞排序樹結構，導致原本排在某些位置的人中獎機率高達原本的 1.5 倍至 2 倍。 | **100% 數學證明均勻**。每種排列組合的出現機率嚴格等於 $\frac{1}{N!}$。 |
| **亂數來源** | **一般偽隨機數（PRNG）**。`Math.random()` 僅為簡單演算法（如 xorshift128+），種子週期固定，理論上可被推算。 | **密碼學級安全亂數（CSPRNG）**。呼叫作業系統底層硬體與雜訊熵源（`crypto.getRandomValues`），不可被預測。 |
| **模數偏差 (Modulo Bias)** | 若直接使用取餘數 `%`，在數字無法整除時會偏向較小數字。 | **具備拒絕取樣（Rejection Sampling）**，徹底消除取餘數偏差。 |
| **演算法複雜度** | $O(N \log N)$ 且執行非預期交換。 | **嚴格 $O(N)$ 線性時間**，效率極高且每次交換皆為獨立事件。 |

## 3. 現行抽獎演算法架構詳解

本系統的隨機取樣邏輯封裝於 `src/utils/lotteryRandom.ts`，由以下三層嚴謹結構組成：

```
┌────────────────────────────────────────────────────────┐
│ 第一層：密碼學安全隨機整數產生器 (getSecureRandomInt)     │
│ - 透過 window.crypto.getRandomValues 取得 32 位元真亂數  │
│ - 採用拒絕取樣 (Rejection Sampling) 排除模數偏差         │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ 第二層：Fisher-Yates (Knuth) 洗牌演算法 (fisherYates)   │
│ - 從陣列尾端向前倒數（i = len-1 downto 1）              │
│ - 每次在 [0, i] 中隨機挑選 j，並精確交換 array[i] 與 array[j]│
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│ 第三層：公平名單選取 (drawRandomWinners / drawSingle)  │
│ - 批次抽出：取洗牌後陣列前 k 個元素                    │
│ - 單人抽出：以無偏隨機索引直接取樣                     │
└────────────────────────────────────────────────────────┘
```

### 3.1 第一層：消除模數偏差的安全隨機數 (`getSecureRandomInt`)

電腦亂數是以整數（例如 32 位元整數 $0 \sim 2^{32}-1$）呈現。如果候選人有 50 人，若直接以 `亂數 % 50` 取餘數，由於 $2^{32} (4,294,967,296)$ 無法被 50 整除，前面幾位員工被選中的機率會稍微高於後面員工（這在統計學上稱為 **Modulo Bias 模數偏差**）。

**本系統的解決方案**：
```typescript
export function getSecureRandomInt(max: number): number {
  if (max <= 1) return 0;
  
  const uint32 = new Uint32Array(1);
  const maxUint32 = 0xffffffff; // 4,294,967,295
  // 計算可被 max 完全整除的最大上限門檻
  const limit = maxUint32 - (maxUint32 % max);
  
  let rand = 0;
  do {
    window.crypto.getRandomValues(uint32);
    rand = uint32[0];
  } while (rand >= limit); // 超過整除門檻的極少數值立即捨棄重抽（拒絕取樣）
  
  return rand % max;
}
```
透過上述機制，每一個數字的出現機率精準至小數點後無數個零，完全排除取餘數產生的百萬分之一偏差。

### 3.2 第二層：Fisher-Yates (Knuth) 洗牌演算法

設候選人總數為 $N$：
1. 我們從最後一位元素 $i = N - 1$ 開始往前走訪。
2. 在索引 $0$ 到 $i$ 之間，隨機抽出一個位置 $j$。
3. 將位置 $i$ 與位置 $j$ 的兩位同仁對調。
4. 遞減 $i$，重複上述步驟直到 $i = 1$ 為止。

**數學證明**：
* 任何一位同仁最後停留在第 $N-1$ 個位置的機率為：
  $$P(\text{最後一位}) = \frac{1}{N}$$
* 任何一位同仁停留在第 $N-2$ 個位置的機率為：
  $$P(\text{次末位}) = \left(1 - \frac{1}{N}\right) \times \frac{1}{N-1} = \frac{N-1}{N} \times \frac{1}{N-1} = \frac{1}{N}$$
* 依數學歸納法，所有元素停留在任何一個位置的機率**全部恆等於 $\frac{1}{N}$**。

**程式碼實作**：
```typescript
export function fisherYatesShuffle<T>(items: T[]): T[] {
  const result: T[] = [...items];
  const len = result.length;
  
  for (let i = len - 1; i > 0; i--) {
    const j = getSecureRandomInt(i + 1); // 隨機挑選 [0, i]
    // 兩者進行交換
    const temp = result[i];
    result[i] = result[j];
    result[j] = temp;
  }
  
  return result;
}
```

### 3.3 第三層：多名額批次抽出與單人抽出

* **批次抽出（例：一口氣抽出 10 名三獎）**：
  先將全體合規候選人以 Fisher-Yates 演算法進行完全均勻隨機置換，接著取出前 10 位同仁。由於每個人的排列機率皆完全均等，因此任何人出現在前 10 位的機率完全相同。
* **單人抽出（例：特獎、缺席棄權補抽）**：
  直接使用 `getSecureRandomInt(candidates.length)`，在候選池中以等機率選取單一得獎者。

## 4. 系統全域應用範圍

本演算法已無縫嵌入系統內所有抽獎環節：

1. **抽獎舞台主畫面（`DrawStage.tsx`）**：
   - 逐筆抽出或單次抽出（`drawRandomWinners`）。
   - 滾動動畫停止的當下，由 Fisher-Yates 核心確認最終客觀得獎者。
2. **大螢幕投影模式（`ProjectorView.tsx`）**：
   - 「逐次抽出模式」：啟動時由 `fisherYatesShuffle` 建立受保護的獨立均勻佇列，依序揭曉各名額。
   - 「一次全抽模式」：由 `drawRandomWinners` 一次性公平開出所有中獎同仁。
3. **現場缺席棄權重抽（`AbsenteeRedrawModal.tsx`）**：
   - 剔除已得獎或不在場同仁後，以 `drawSingleWinner` 自合規同仁中公正補抽。

## 5. 常見問題解答 (FAQ)

### Q1：畫面上的轉動跑馬燈動畫，會影響實際抽中的人嗎？
**不會。**
轉動跑馬燈動畫純粹是活動現場的視覺與聽覺娛樂效果（視覺暫留與儀式感）。抽獎結果是在動畫結束的計算關鍵時刻，由 Fisher-Yates 演算法自「真實候選人池」中客觀選出，動畫過程中的跳動完全不干涉抽獎核心邏輯。

### Q2：如果有員工匯入 Excel 時排在第一筆或最後一筆，會有影響嗎？
**完全沒有影響。**
在舊式的 `sort()` 排序寫法中，排在名單開頭的確有較大概率被留在前面；但在 **Fisher-Yates** 演算法中，每一個位置在走訪過程中都有相等的機率被任意調換至任何位置，原始名單的排列順序對最終中獎機率完全為零影響。

### Q3：加碼獎或第二輪抽獎時，會不會抽到已得獎的人？
本系統具備嚴格的業務防呆控制：
* **一般獎項（正規池）**：已中獎同仁會即時被移至中獎清冊，自動自候選池扣除，**絕不會重複中獎**。
* **老闆特別加碼獎**：提供獨立的加碼池規則（可設定全體同仁重新具備資格，或僅限未中獎者加碼）。
* **輪次機制（Round Management）**：若開啟「多輪抽獎允許跨輪重複中獎」，系統會在輪次交替時彈窗確認，並明確記錄每筆中獎所屬輪次。
